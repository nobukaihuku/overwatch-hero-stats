# 公式更新直後の部分欠損を許容する収集設計

## 目的

公式サイトの更新・部分障害で一部のマップ、ティア、ヒーロー指標が一時的に返らない場合でも、取得できた統計を最後まで収集する。ただし、別のフィルタの値を誤って保存したり、欠損を0として扱ったりしない。

## 失敗分類

- 通信、HTTP、JSON解析、`rates.selected` 欠損、空の行、行ID欠落はフィルタ単位の再試行対象。
- 第1パスで失敗したフィルタは第2パスで残り回数を使って再取得する。1フィルタの試行上限は3回。
- `rates.selected` が要求値と異なる場合は、別フィルタのデータ混入を示すため即時終了する。競技`rq`のrun開始時候補判定だけは既存の`rq=2`/`rq=1`フォールバックを使う。
- 再試行後も取得できないフィルタはスナップショットから除外し、`collectionQuality.failedFilters`に理由を残す。
- 直近スナップショットがある場合、各応答のヒーロー行数が直近のヒーロー集合の2/3未満なら、単一応答の大規模欠損として保存しない。

## 値の欠損

`win`、`pick`、ランクの`ban`が公式に未提供の場合は、既存の数値正規化により`null`として保持する。0への補完は行わない。応答からヒーロー行自体がない場合は、現在runと直近スナップショットから作った`heroUniverse`との差分として`incompleteSnapshots`に記録する。

## 保存ゲート

- `map`軸またはその`input/map/region`グループの取得率が2/3未満なら、そのマップの成功フィルタも保存対象から外してマップ全体を隔離する。これにより、同一マップ内の歯抜け値を完全な統計として扱わない。
- 隔離したマップの全フィルタを失敗数へ含めたうえで、既存の全体失敗率5%上限を維持する。隔離後に保存対象が0件になる場合も保存しない。
- 隔離後の`input`、`map`、`region`、`mode`、`rq`、`tier`の各軸と、`input/map/region`グループについて、取得率が2/3未満の偏った欠損は保存しない。
- 既存の正準8tier、ランクBAN率、QP/ランク同一化、重複排除の検査は変更しない。

## Payload

既存の`filterPlan`と`snapshots`は維持し、追加の`collectionQuality`に次を保存する。

- `status`: `complete` または `partial`
- `failedFilters`: フィルタ、理由コード、試行回数
- `quarantinedMaps`: 隔離したマップと隔離前の期待数、取得数、取得率
- `heroUniverse`: 当日と直近スナップショットで観測したヒーロー集合
- `incompleteSnapshots`: 不足ヒーローと不足指標
- `coverageByAxis`、`coverageByInputMapRegion`: 期待数、取得数、取得率

既存利用側が追加フィールドを無視しても、従来の`filters`と数値形状は利用できる。部分データを完全データとして表示するかどうかは、別リポジトリのWeb側で別途判断する。

## 検証

オフラインモックで、一時的欠損の回復、恒久欠損の部分保存、不完全マップの全体隔離、`null`保持、軸集中欠損の保存拒否、既存の競技`rq`フォールバック、タイムアウト再試行を検証する。公式APIへの実行とworkflowの再実行は、この設計の検証後に別途承認する。
